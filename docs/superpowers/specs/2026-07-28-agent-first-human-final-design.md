# Agent-first、人工终审协作模式

日期：2026-07-28

## 决策

`client-collaboration-hub` 的日常使用者不应充当两个客户端的表单录入员。

第一阶段采用项目级策略：

```text
Agent 自动推进：开启
最终审查：人工
自动 DONE：关闭
```

Codex 与 CC-HAHA 仍是平等、独立的原生客户端。中枢不启动、接管或模拟任一客户端；它只接收客户端主动提交的结构化协作事实，校验、持久化并把需要人类决定的事项放进审查队列。

## 目标

1. 让 Agent 自行登记其职责范围内的任务进展、消息和 Evidence。
2. 让操作者只处理最终审查、返工结论、阻塞解除和异常候选。
3. 让项目、客户端、设备、适配器和事件游标从已登记上下文自动推导，而不是反复输入。
4. 保留任务、Evidence、版本冲突和审查结论的完整审计历史。
5. 在收集数轮真实交接包后，可将项目策略升级为 Agent 自审，而不重写任务和 Evidence 格式。

## 非目标

- 不自动控制 Codex、CC-HAHA、AO、sidecar、PTY 或浏览器。
- 不伪造客户端完成、测试结果或审查结论。
- 不在本阶段加入远程网络服务、云同步、轮询守护进程或 GUI 自动化。
- 不允许 Agent 在 `human_final` 策略下自行写入 `DONE`、批准或正式返工结论。

## 策略模型

项目记录增加协作策略，默认值如下：

```yaml
collaboration_policy:
  submission_mode: agent_auto
  final_review: human
  auto_done: false
```

未来的 Agent 自审只变更策略，而不改变任务状态机：

```yaml
collaboration_policy:
  submission_mode: agent_auto
  final_review: agent
  auto_done: true
```

策略变更本身必须由人工确认，并追加一条可审计事件。

## Agent 提交通道

新增“Agent 提交”概念，而不是要求客户端遥控网页。

客户端在自身原生会话完成工作后，通过本地 `collab` 命令或同等的本地适配器提交结构化候选。提交必须至少包含：

- 来源客户端 ID；
- 任务 ID；
- expected version；
- 候选动作；
- Evidence、消息或阻塞说明；
- 可选的交接包/候选响应引用。

创建任务的候选还必须包含项目、标题、目标、验收标准、创建者和审查者；中枢不从自由文本推断这些事实。

第一阶段的提交通道是同一台受信任本机上的显式本地命令。`source_client_id` 必须匹配已登记客户端及其能力，但它不是跨设备或远程身份认证；远程凭据和签名机制明确延后。

中枢在单次提交中完成身份能力、状态、版本、Evidence 引用和项目策略校验。校验成功后，允许的非终态事件直接追加；失败时保留原始候选并进入异常队列，不改变任务状态。

第一阶段允许自动登记：

| 来源 | 允许的候选 |
|---|---|
| Codex | 创建任务、分配、说明、审查材料补充 |
| CC-HAHA | 接受、恢复、消息、Evidence、提交审查、登记阻塞 |
| 任意来源 | 不可直接写入批准、返工结论或 DONE |

人类在网页中仍独占：

```text
批准完成
要求返工
解除/重新界定 BLOCKED
修改项目协作策略
```

## 状态机与责任边界

状态机保持不变：

```text
DRAFT → ASSIGNED → WORKING → REVIEW → DONE
                            ↘ REVISION_REQUIRED → WORKING
                  ↘ BLOCKED
```

在 `human_final` 模式：

- Agent 可以把任务推进至 `REVIEW`，但不能从 `REVIEW` 推进至 `DONE` 或 `REVISION_REQUIRED`。
- `BLOCKED` 是通知人类的正式事实，不是自动重试信号。
- 新 Evidence 会保留旧审查材料；如果已有审查结论受新 Evidence 影响，界面明确标记需要重新审查。

## 网页控制台

日常导航收敛为三项：

```text
待我审查
协作活动
交接历史
```

### 待我审查

默认首页只显示：

- 进入 `REVIEW`、等待人工结论的任务；
- `BLOCKED` 任务；
- 被拒绝、版本冲突或权限不足的 Agent 候选。

审查页只显示目标、验收标准、Evidence 覆盖、客户端摘要和两个正式按钮：`批准完成`、`要求返工`。

### 协作活动

以账本方式显示 Agent 提交、Evidence、版本、交接和失败原因；不显示常驻编辑表单。

### 交接历史

对当前任务自动推导：目标客户端、适配器、本机设备和事件游标。操作者只选择“生成下一份交接包”或查看历史包。

默认输出位置使用本机运行目录下由程序创建的新包目录；不要求操作者手填绝对路径。候选响应由客户端提交通道导入，网页仅显示校验结果与审查材料。

## 固定上下文的自动推导

以下值不得要求日常重复填写：

| 值 | 推导来源 |
|---|---|
| 项目 | 当前任务的 `project_id` |
| 执行客户端 | 分配记录 |
| 审查客户端 | 任务 `reviewer` |
| 本机设备 | 当前浏览器/运行目录的默认 Binding |
| 适配器 | 目标客户端的默认手工交接适配器 |
| expected version | 当前任务快照 |
| after-event | 上次发往同一目标的已确认交接游标 |

同一任务首次发往某个目标时，`after-event` 固定为 `0`；后续包从该目标上一次已确认包的游标继续。推导不唯一或 Binding 不可用时，界面显示一个明确的选择/修复项，而不是回退为整页自由文本。

## 失败语义

| 情况 | 结果 |
|---|---|
| 版本不一致 | 不写入；候选进入异常队列并标明当前版本 |
| 无能力/越权动作 | 不写入；保留候选和拒绝原因 |
| Evidence 引用缺失 | 不写入依赖它的提交；Evidence 可单独补交 |
| Binding 不可用 | 可查看任务，但不能生成本机解析的交接材料 |
| 候选格式无效 | 不写入；显示字段级错误 |
| Agent 试图批准/DONE | `human_final` 下拒绝并记录策略拒绝事件 |

## 第一阶段范围

1. 项目协作策略及其人工变更审计。
2. Agent 提交命令/本地适配器：接收候选、校验并自动登记允许的非终态事件。
3. 人工审查队列和精简任务审查页。
4. 固定上下文自动推导与选择器，移除日常手工输入的协议字段。
5. 自动生成交接包目录与交接历史游标。
6. 候选拒绝/版本冲突/Binding 不可用的异常队列。

## 延后范围

- Agent 自审和自动 `DONE`；
- 远程身份认证与跨设备网络同步；
- 自动发送/启动原生客户端；
- AO、sidecar、ConPTY 或 GUI 自动化；
- 自动 push、merge、部署或外部写入。

## 验收标准

1. CC-HAHA 能以结构化提交把一个已分配任务推进到 `REVIEW`，不经人工填表。
2. Codex/操作者在网页中只需阅读 Evidence 并做批准或返工结论。
3. UI 不要求重复填写已登记的项目、设备、客户端、版本或交接参数。
4. 错误候选、越权动作和版本冲突均不改变任务状态，且可被审查。
5. 所有自动登记的事件都记录来源客户端、策略决定、版本和关联 Evidence。
6. 在至少数轮真实交接包闭环后，才能评估是否启用 `agent` 最终审查策略。
